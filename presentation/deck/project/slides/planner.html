Is it an LP? Yes. We just solve it faster

What we minimise. Grid import over the next 36 hours, each kWh weighted by w = CO₂ + 0.27 × price. Limits: 1,500 kW, 6,000 kWh, 95 % efficiency each way. Energy sent to the grid earns nothing.

How we solve it. The value of stored energy is convex and piecewise linear, so we only keep its slope: a sorted list of (value per kWh, width). Going one hour back in time is a merge of two sorted lists. No grid over the state of charge.

Uncertainty. The load and solar error distributions are combined into 9 equally likely net-load scenarios for each of the next 12 hours. The value of stored energy is averaged half-and-half between the signal forecast and 20 sampled error paths.

Control. We re-plan every hour with the newest readings and only apply the first command.

(about 35 s) So is it a linear programme? Yes: minimise grid import over 36 hours, weighted by CO2 plus 0.27 times price. But we solve it as an exact dynamic programme: the value of stored energy is piecewise linear, so going one hour back is just merging two sorted lists. Same answer as scipy to eleven decimals, twenty times faster. That speed lets us plan on scenarios instead of one forecast, which was our biggest gain: 0.71 points with the same forecasts.
